# Task matching and page scrolling

- Problem: Jira issues and ClickUp tasks disappear from the card selectors after the user is unassigned, so description-prefix matching could not link those cards.
- Choice: resolve missing codes through each service's read API. ClickUp lookups stay scoped to the team already selected on the card. Jira lookups follow the cross-instance rules below.
- Change: the match buttons deduplicate codes, reuse known items, fetch missing items, add successful results to the selector stores, then link cards. Failed or inaccessible lookups remain unchanged and produce a summary warning.
- Jira matching rules (supersede the per-instance scoping of `7b168a7`, which stopped cards with the hard-coded main URL from matching issues on other instances): the Jira button builds one pool of loaded issues across the main instance and every additional instance. A card with no `jiraUrl`, or with the main URL, matches the main instance first, then a unique match on another instance (an ambiguous key stays unlinked), and its `jiraUrl` is set to the instance it matched. A card explicitly set to a non-main instance is authoritative: it matches and fetches only on its own instance and is never moved.
- Jira fetching: only keys missing from every loaded list are requested. Non-authoritative keys are tried on the main instance first, then the others, stopping at the first success; authoritative keys are requested once on their own instance with no fallback. Lookup requests skip the global error toast, so a miss yields one summary warning listing the missing keys ("Could not find Jira issue(s): ABC-1179, ..."; first five keys, then "and N more"). The earlier "card(s) need a Jira instance" notice was removed because cards without a URL now match across instances. ClickUp matching is unchanged and never runs from the Jira button.
- Instance normalization: the card-creation default and the WorkLogItem save fallback use `normalizeServiceScope` instead of `slice(8)`, so the stored `jiraUrl` is a bare host in the same form as the pool.
- Scroll correction: removed fixed heights from the application container, tabs, and panels. Date headers and the Total table retain their own horizontal overflow; card panels expand naturally and the document owns vertical scrolling.

Tests cover native/custom codes, deduplication, hydration, scoped store linking, missing scopes, inaccessible tasks, and moved Jira key aliases. Targeted ESLint and `git diff --check` passed; `npm run build` passed with existing Vite/Sass deprecation and chunk-size warnings.
- Browser evidence: local fixture with 9 cards in one day and 22 date tabs, two Jira instances and two ClickUp workspaces. Button clicks issued 3 Jira GETs and 4 ClickUp GETs, deduplicated repeated codes, reused cached tasks, displayed fetched labels, and preserved inaccessible cards. Native ClickUp ID resolved to its custom-key label. At 1280 x 720, the card panel had clientHeight = scrollHeight = 1708px, overflowY = visible; only HTML had vertical overflow. Wheel scrolling changed document scrollTop while the panel stayed at 0. Temporary fixture files were removed after verification.
- API contracts checked against [Jira Get issue](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/#api-rest-api-3-issue-issueidorkey-get) and [ClickUp Get Task](https://developer.clickup.com/reference/gettask). Matching sends only read requests through the existing proxy; no worklogs or issues/tasks are written remotely.
