# Task matching and page scrolling

- Problem: Jira issues and ClickUp tasks disappear from the card selectors after the user is unassigned, so description-prefix matching could not link those cards.
- Choice: resolve missing codes through each service's read API and always scope lookups to the Jira instance or ClickUp team already selected on the card.
- Change: the match buttons deduplicate codes, reuse known items, fetch missing items, add successful results to the selector stores, then link cards. Failed or inaccessible lookups remain unchanged and produce a summary warning.
- Scroll correction: removed fixed heights from the application container, tabs, and panels. Date headers and the Total table retain their own horizontal overflow; card panels expand naturally and the document owns vertical scrolling.
- Validation (2026-10-07): 10 tests passed via `cd react-app && node --experimental-default-type=module --test src/helpers/matchWorklogTasks.test.js`. Tests cover native/custom codes, deduplication, hydration, scoped store linking, missing scopes, inaccessible tasks, and moved Jira key aliases. Targeted ESLint and `git diff --check` passed; `npm run build` passed with existing Vite/Sass deprecation and chunk-size warnings.
- Browser evidence: local fixture with 9 cards in one day and 22 date tabs, two Jira instances and two ClickUp workspaces. Button clicks issued 3 Jira GETs and 4 ClickUp GETs, deduplicated repeated codes, reused cached tasks, displayed fetched labels, and preserved inaccessible cards. Native ClickUp ID resolved to its custom-key label. At 1280 x 720, the card panel had clientHeight = scrollHeight = 1708px, overflowY = visible; only HTML had vertical overflow. Wheel scrolling changed document scrollTop while the panel stayed at 0. Temporary fixture files were removed after verification.
- API contracts checked against [Jira Get issue](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/#api-rest-api-3-issue-issueidorkey-get) and [ClickUp Get Task](https://developer.clickup.com/reference/gettask). Matching sends only read requests through the existing proxy; no worklogs or issues/tasks are written remotely.
- Validation scope: real authenticated Jira/ClickUp lookups remain unverified; browser checks used controlled API fixtures.
- Release preparation: preserve the already-deployed Compare table date-ordering fix in a separate source commit. The live bundle `index-WC-VHAbl.js` matched the pre-existing local Firebase artifact (SHA-256 `ef98492106565c49e2daf93b97ef93a629a35396af21430e98ff78d9b8eb5bd9`) before this release.
